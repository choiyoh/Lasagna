# ADR-0001: 앱 내장 Google Drive API 동기화 도입

- 상태: 승인
- 날짜: 2026-10-12

## 맥락
설계 문서 v0.1은 자체 동기화를 두지 않는다(N3·N4). 여러 기기에서 쓰려면 사용자가 고른 동기화 폴더(iCloud, Syncthing 등)에 볼트를 두게 되어 있다. 하지만 사용자는 Google Drive로 동기화하기를 원하고, 동기화 상태와 충돌을 앱 안에서 제어하는 쪽을 골랐다.

## 결정
앱에 Google Drive API 기반 양방향 동기화를 **옵트인 모듈**로 넣는다. 설계 문서의 다음 항목을 이렇게 바꾼다.

| 항목 | 기존 | 변경 |
|---|---|---|
| G2 100% 로컬·오프라인 | 네트워크 없음 | 동기화를 켜지 않으면 그대로 오프라인. 켜면 SyncWorker만 Google 도메인 허용 목록으로 통신 |
| G3 / N1 계정 없음 | 로그인 없음 | 앱 계정은 없음. 동기화할 때만 사용자 본인 Google 계정을 OAuth(PKCE + loopback)로 연결 |
| N4 자체 동기화 없음 | 제외 | Drive API 동기화 제공(앱 자체 서버는 여전히 없음) |

## 세부
- 스코프는 `drive.file`만 쓴다. 앱이 만든 파일에만 접근한다.
- 사용자 전용 빌드에는 사용자가 만든 OAuth client ID/secret을 main 번들에 내장할 수 있다. 저장소·CI 빌드에는 값을 넣지 않는다.
- 직접 입력한 클라이언트가 있으면 내장 클라이언트보다 우선한다. 토큰은 발급한 클라이언트에 묶고, 클라이언트를 바꾸면 재사용하지 않는다.
- 내장 값은 renderer·preload에 넣지 않는다. 빌드 결과물에는 값이 포함되므로 공유 범위를 사용자가 관리한다.
- refresh token은 Electron `safeStorage`(OS 키체인)로 암호화한다.
- 네트워크 코드는 SyncWorker에만 둔다. 범용 네트워크 프록시는 두지 않는다(S4 유지).
- 충돌 처리는 1단계의 블록 단위 3-way 병합을 다시 쓴다. base 스냅샷은 `.nopsidian/sync/base/`에 둔다.

## 결과
- 동기화 엔진 구현 비용(약 4~5주)이 생긴다. 로드맵에 3.5단계로 넣었다.
- 동기화를 끈 상태의 보안·프라이버시 속성은 설계 문서와 같다.
- 사용자 전용 빌드 결과물은 비밀이 포함된 개인 파일로 취급한다. 공개 배포용 빌드는 내장 값 없이 수동 설정으로 만든다.
